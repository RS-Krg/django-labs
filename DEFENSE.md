# Подготовка к защите

## Лабораторная №0.1 — helpdesk

- `created_by` берётся из сессии, а не из формы, чтобы сотрудник не мог назначить автором другого пользователя.
- `visible_tickets()` фильтрует заявки до поиска и получения объекта. Чужой номер даёт 404, не раскрывая существование заявки.
- ИТ-отдел получает право `change_ticket` через группу. Поле исполнителя формы ограничено членами этой группы и проверяется при POST.
- `redirect` после сохранения предотвращает повторный POST при обновлении страницы; CSRF-токен защищает формы изменения данных.
- Сотрудник редактирует только свою новую заявку; обработка доступна только ИТ-отделу.

## Лабораторная №0.2 — каталог

- `accounts.User` создан в первой миграции до первого `migrate`, чтобы смена модели пользователя позже не требовала перестройки БД.
- Цена хранится в `DecimalField`, положительность дополнительно закреплена `CheckConstraint`.
- `search_index` заполняется в `save()` в нижнем регистре. Это даёт поиск по кириллице на SQLite; `bulk_update` и прямой `update()` индекс не обновляют.
- Параметр сортировки проходит через белый список; `Paginator.get_page()` безопасно обрабатывает неверный номер.
- `seed_catalog` использует `get_or_create` по уникальным slug, поэтому повторный запуск не создаёт копий.

## Лабораторная №0.3 — заказы

- Корзина хранит только строковый ID товара и целое количество в сессии; текущая цена и остаток читаются из БД.
- Сервис `place_order` создаёт заказ и списывает остатки внутри одной транзакции. Если товара не хватает, исключение откатывает всё; цена копируется в `OrderItem`.
- При отмене остаток возвращается один раз. Чужие заказы ищутся только через `request.user.orders`, поэтому дают 404.
- Менеджер имеет `is_staff` и права группы, но не `is_superuser`; переходы статуса разрешены только действиями admin panel с фильтром исходного статуса.

## Итоговый проект Д2–М4

- `Brand`, `Product`, `ProductVariant`, `Category`, `Order`, `OrderItem` дают шесть предметных моделей и нужные связи.
- Остаток хранится у `ProductVariant`; корзина использует ID варианта. При заказе условный `UPDATE stock >= quantity` и транзакция исключают частичное списание. В позиции хранится снимок размера, названия и цены.
- У товара без доступных вариантов нет кнопки покупки. Фильтр размера выбирает только варианты с положительным остатком.
- Отчёты строятся через `annotate`, `aggregate`, `Sum`, `Count`, `TruncDate`; отменённые заказы исключаются из выручки. Доступ проверяется по группе или суперпользователю, а даты валидирует форма.
- Вариант Д2–М4 должен быть утверждён преподавателем после проверки списка группы. Историю из 15 коммитов, распределённых по неделям, нельзя добросовестно создать задним числом.
